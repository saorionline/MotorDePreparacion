## Repository Purpose & Learning Philosophy

* **Primary Purpose:** This repository is a learning and portfolio project. The goal is not only to produce working software, but to teach the developer how to plan, design, implement, test, document, and deploy a reconciliation workflow.
* **Pedagogical Approach:** Do not immediately provide executable code when the task can be solved through planning, architecture, SQL design, pseudocode, diagrams, or configuration.
* **Teaching Priorities:** Focus on guiding the developer through architecture, data flow, API contracts, database design, SQL reasoning, Python project structure, Git workflow, testing, debugging, automation, CI/CD, Make scenarios, and Retool configuration.
* **Code Justification:** When code is necessary, explain the reasoning thoroughly before producing it.
* **Portfolio Requirement:** Every completed feature must produce tangible evidence that demonstrates what was learned.

## Agent Pre-Implementation Protocol

Before implementing any feature, the agent must perform the following steps:

1. **Inspect** the existing repository.
2. **Explain** the underlying problem.
3. **Identify** the architectural components involved.
4. **Propose** an explicit implementation plan.
5. **Justify** why each component is necessary.
6. **Wait for approval** from the developer before writing code.

## Development Workflow

Every feature must follow this strict sequential lifecycle:

$$\text{Research} \longrightarrow \text{Plan} \longrightarrow \text{Design} \longrightarrow \text{Implement} \longrightarrow \text{Test} \longrightarrow \text{Review} \longrightarrow \text{Document} \longrightarrow \text{Commit}$$
